## Project Brief

This project has a Project Brief at `PROJECT.md`. **Read it before doing any
substantive work in this repo.** It states what the project is for, the
success criteria work is measured against, and what is explicitly out of
scope.

- **Before proposing or starting work**, check the objective and success
  criteria. Work that advances no criterion is not automatically wrong, but
  say so out loud before starting it rather than after.
- **Before adding a feature**, check the out-of-scope list. If it is listed
  there, say so instead of building it — those exclusions are deliberate and
  carry their reasons.
- **Treat the brief as the target, not a description of the code.** Where the
  two disagree, that is a finding worth reporting. Do not edit the brief so
  that it matches what exists.
- **The review log** at the bottom of `PROJECT.md` links dated reviews in
  `docs/reviews/`. The most recent one states where things actually stand,
  including what is unverified.

To grade progress against the brief, use the `project-status-review` skill.
To change the brief, use `project-expansion-review` — it is the only thing
that should amend it.
