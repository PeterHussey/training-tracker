## Looks done vs is done

- **Attacked and survived:** empty inputs, null fields, zero-duration, malformed JSON, corrupted files, idempotent storage, deterministic computation, session windowing
- **Only ever watched to succeed:** live Garmin refresh, Streamlit UI rendering, chart propagation across date-window, activity comparison display
- **Could not be probed:** interactive UI behavior (requires running Streamlit); live Garmin auth (requires credentials not available in this environment)

## Debt

- `garminconnect==0.3.2` is pinned because its own HTTP layer stalls on Cloudflare; the workaround (`garmin_http.py`) is well-documented but adds a maintenance surface.
- The `store._migrate()` method uses in-place `ALTER TABLE` with no versioning — works for additive changes but will be fragile if a non-additive migration is ever needed.

## Risk

- Fresh install with no tokenstore and no op/env credentials hits a `PermissionError` on the real tokenstore path before falling back — could confuse a first-time user. The error message is not surfaced clearly.
- The 90s hard timeout on Garmin refresh is unit-tested for the fetch window narrowing, but no test exercises a full end-to-end refresh with a large activity history.
- Streamlit session state holds the entire metric view in memory; for very large histories (many years of daily activities) this could become a concern.
